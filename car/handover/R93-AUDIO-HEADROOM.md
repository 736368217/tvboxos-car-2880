# r93 音频前级余量与逐采样限幅

2026-11-21：`3.1.0-car.7-r93` / versionCode 65 处理「车机硬件音效开启时声音发糊、像削峰」的反馈；包名、签名与覆盖安装契约不变。r92 的音量 A/B 行为保留。

## 为什么会发糊

零跑 B01 的【动漫·天籁进化版】等硬件音效在**主音量衰减之前**给通道与频段加正增益。r92 把 App 输出天花板定在 `-1.5 dBFS`（0.841395），响段峰值再叠加车机前级增益，就会先撞进车机 DSP 自己的限幅/削波器——此时主音量再小，听到的已经是压平的声音。

## 本版改动

- 采样峰值天花板降到 **`-6.0 dBFS`（0.501187f）**，为车机前级留出约 6 dB 数字余量。这是采样峰值，不是过采样真峰值。
- 目标与压缩同时下调，避免压缩器与限幅器互掐：

| 预设 | 目标响度 | 最大提升 | 压缩阈值 | 比率 |
|---|---|---|---|---|
| 车载均衡 | -22.0 dBFS | +9 dB | -18 dBFS | 2.0:1 |
| 高速压缩 | -19.5 dBFS | +12 dB | -17 dBFS | 3.2:1 |

- 删除 10 ms 块起点对增益的 `onsetBound` 硬覆盖，块与块之间只从上一块的末值继续。
- 限幅改为**逐采样**：超限的那一个采样就压低，绝不越界；恢复按 **80 ms** 逐采样指数释放，不再整块 10 ms 硬缩放（100 Hz 级调制毛刺的来源）。
- DRC 关闭（手动增益）保持无状态：每一块按块内峰值等比缩放，>100% 时仍受 -6 dBFS 保护，不会因为一次瞬态把后面整段压下去。
- 噪声门以下不叠加 AGC 提升，噪声与静音原样通过。

## 已测数据

主机回归（26 项全通过）：

- 车载均衡：轻声 −30 → −22 dBFS，响段 −14 → −20 dBFS，稳态差 16 → 2 dB。
- 高速压缩：轻声 −30 → −19.5 dBFS，响段 −14 → −19.5 dBFS。
- 5 倍增益瞬态：输出峰值 0.501190，未越 −6 dBFS。

MuMu API 35 设备（临时实例 7，用后已删除，机主安装未覆盖）：

- 诊断片走 EXO PCM 链路：`mode=CAR_BALANCED`，增益从约 1.40 回落到约 0.32，`outPeak` 最大 0.2733，未触天花板。
- 切换原声：`mode=ORIGINAL bypass=true`，再切回恢复 `CAR_BALANCED`。

## 临时音量测试入口

设置 → 高级设置 →「播放与声音」→ **音量测试片（临时）** → 播放。测试片是内置的 20 秒诊断剪辑（`app/src/main/assets/audio-diagnostic.mp4`），播放页底部按钮可即时在「增强音量 / 原始声音」之间切换，方便同一段素材对比。

这个入口只用于本轮实车/实机标定，标定结束后连同 Activity、布局、manifest 条目与资源一起删除；它不是产品功能。

## 边界

- `-6 dBFS` 是根据车机前级增益估算的余量，不是实测 THD 结果。真车听感、实际 DSP 曲线与音量大小时的削峰情况仍需实车验证。
- MuMu API 35 + ARM 翻译只证明链路与数值行为，不代表 B01 API 32 的 OEM 音频路由。
- 诊断片是本地固定素材，不证明远端片源可用性。
